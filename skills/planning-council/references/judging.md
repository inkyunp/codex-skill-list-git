# 심사 방식

## 왜 점수가 아니라 쌍대 비교인가

후보 네 개에 82점·79점·76점을 매기면 숫자는 그럴듯하지만 실제 차이를 구분하지 못한다. 절대점수는 심사자 내부의 모호한 기준에 의존하고, 3점 차이가 무엇을 의미하는지 아무도 설명할 수 없다.

둘씩 비교하면 심사자가 **구체적 차이를 지목**해야 한다. "C1이 C3보다 낫다, 왜냐하면 C3의 핵심 가정이 미검증 시장 반응에 의존하기 때문" 같은 문장이 나온다. 이것이 통합 단계에서 실제로 쓰인다.

## 쌍대 비교 질문

모든 후보 쌍에 대해:

```
후보 A vs 후보 B
1. 어느 쪽이 목표에 더 부합하는가?
2. 어느 쪽의 핵심 가정이 더 강한가?
3. 어느 쪽이 실행 가능성이 높은가?
4. 어느 쪽이 실패해도 더 빨리 검증 가능한가?
5. 최종 승자와 결정적 이유는 무엇인가?
```

후보가 3개면 3쌍, 4개면 6쌍이다. 6쌍을 넘으면 토너먼트로 줄인다.

## 토너먼트 진행

후보가 5개 이상이거나 클러스터링 후에도 후보가 많으면:

```
1라운드: C1 vs C2, C3 vs C4  → 각 승자
2라운드: 승자끼리 비교        → 최종 승자
```

탈락한 후보의 **강점 메모는 버리지 않는다**. 통합 단계에서 결합 재료로 쓴다.

## 편향 통제 체크리스트

심사자를 띄우기 전에 전부 확인한다.

- [ ] 후보에서 작성 모델명·역할명을 제거했는가 (`C1`, `C2` 라벨만)
- [ ] 심사자마다 후보 순서를 다르게 섞었는가
- [ ] 두 심사자가 서로 다른 회사 모델인가
- [ ] 평가기준을 명시적으로 전달했는가
- [ ] 라벨↔모델 매핑표를 메인만 보관하고 있는가

LLM 심사자는 자신 또는 자신과 유사한 모델이 만든 문체를 선호하는 경향을 보인다. 그래서 익명화만으로는 부족하고 교차 회사 배치를 함께 건다. 반대로 "타사 모델이 심사하면 자동으로 공정하다"도 성립하지 않는다. 네 가지를 **동시에** 걸어야 한다.

## 심사 결과가 갈릴 때

judge-A와 judge-B의 1위가 다르면:

1. 두 심사자의 **결정적 이유**를 나란히 놓는다
2. 어느 논거가 브리프의 평가기준에 더 직접 연결되는지 본다
3. 한쪽이 사실 오인에 근거했다면 그 판정을 배제한다
4. 둘 다 타당하면 **평가기준의 우선순위**로 결정한다. `mode`별 가중치를 적용한다
5. 그래도 갈리면 두 후보의 강점을 결합할 수 있는지 검토한다

심사자를 추가로 띄워 다수결하지 않는다. 3인 다수결은 판단을 개선하지 않고 비용만 늘린다. 메인이 논거를 읽고 결정하며, 그 결정 근거를 보고서에 남긴다.

## 심사자가 하지 말아야 할 것

- 분량이 긴 후보를 충실하다고 평가하는 것
- 문장이 유창한 후보를 우수하다고 평가하는 것
- 새로운 아이디어를 제안하는 것 (심사자의 역할이 아니다)
- 모든 후보를 "각각 장점이 있다"고 무승부 처리하는 것 — 반드시 승자를 지목하게 한다
