# subagent-delegation

서브에이전트를 쓰는 이유는 세 가지다. 이 중 하나도 해당하지 않으면 위임하지 않는다.

1. **비용** — 좋은 모델을 기계적인 일에 쓰지 않는다.
2. **컨텍스트 보호** — 지저분한 조사 원문이 메인 컨텍스트를 채우지 않게 한다.
3. **독립성** — 작성자와 검토자를 분리한다. 모델은 자기 작업물에 관대하다.

위임 자체는 공짜가 아니다. 서브에이전트가 늘면 총 토큰은 오히려 커진다. 위 세 이유가 없는데 나누면 손해다.

메인 에이전트가 **요구사항 해석·작업 분해·충돌 판정·최종 산출물**을 직접 소유한다. 서브에이전트는 할당된 범위만 수행하고, 다시 서브에이전트를 띄우지 않는다(leaf agent).

## Phase 0 — 등급 판정

되묻지 말고 등급을 정한 뒤 아래 한 줄을 고지하고 바로 진행한다.

```
subagent-delegation v1 — tier: D{0|1|2|3} / 위임: {역할 목록 또는 없음} / run_id: {YYYY-MM-DD-NNN}
```

| 등급 | 조건 | 절차 |
|---|---|---|
| **D0** 직접 수행 | 단순 질문, 오탈자, 한 파일 확인, 한 번의 검증으로 끝남 | 위임하지 않는다 |
| **D1** 탐색 위임 | 코드 구조 조사, 문서 비교, 로그 요약, 호출 관계 추적 | Explorer 1~3명 병렬 → 메인이 종합 |
| **D2** 실행+교차 리뷰 | 코드 수정, 지속되는 산출물 생성 | (Explorer) → Executor → 다른 회사 Reviewer → 수정 → 재검토 1회 |
| **D3** 고위험 | 보안·인증·권한, 데이터 삭제, 마이그레이션, 공개 API 변경, 대규모 리팩터링 | Explorer 최대 2명 → 메인이 계획 확정 → Executor → Reviewer → 충돌 시 Arbiter |

애매하면 한 단계 낮게 시작한다. 부족하면 올리는 편이 처음부터 D3로 가는 것보다 싸다.

## Phase 1 — 위임 계약

모든 호출은 계약을 갖춘다. **OBJECTIVE / SCOPE / WRITE_PERMISSION / DONE_WHEN / RETURN_FORMAT** 다섯 개가 없으면 서브에이전트를 띄우지 않는다.

계약 전문 템플릿과 역할별 프롬프트는 **references/delegation-contract.md**에 있다. 그대로 복사해 채운다.

`fork_turns: "none"`이므로 메시지는 **완전히 자기완결적**이어야 한다. 서브에이전트는 사용자 요청도, 이 스킬의 존재도, 다른 서브에이전트의 존재도 모른다. 필요한 배경·파일 경로·diff는 메시지에 통째로 넣는다.

```
spawn_agent(
  task_name="explorer_auth_flow",
  fork_turns="none",              # 필수. 전체 히스토리 포크는 model override를 거부한다
  model="gpt-5.6-luna",
  reasoning_effort="low",
  message=<계약 전문>
)
```

## Phase 2 — 역할

| 역할 | 권한 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| **Explorer** | 읽기 전용 | 파일·문서·로그 조사, 주장마다 `path:line` 근거, 확인된 사실과 추론 구분 | 수정, 커밋, 파괴적 명령 |
| **Executor** | 지정 경로만 쓰기 | 할당된 변경 구현, 기존 관례 준수, 수정 파일과 검증 결과 보고 | 범위 확장, 같은 실패 3회째 땜질 |
| **Reviewer** | 읽기 전용 | 요구사항 대비 적대적 검토, `PASS/FAIL` + 근거 | 코드 직접 수정, 취향 논쟁 |
| **Arbiter** | 읽기 전용 | 충돌한 주장만 판정 | 작업물 재작성 |

Executor는 지정 범위를 벗어나는 변경이 필요하면 **작업을 확장하지 않고 보고**한다. 동일한 실패가 두 번 지속되면 세 번째 수정 대신 원인 가설을 반환한다.

## Phase 3 — 교차 리뷰

**LLM 리뷰보다 자동 검증을 먼저 돌린다.** 테스트·타입 검사·린트·빌드·스키마 검증에서 잡히는 것을 모델에게 찾게 하지 않는다.

Reviewer에게는 **요구사항 / 최종 diff / 관련 코드 / 자동 검증 결과**만 전달한다. 작성자의 긴 설명, 자신감 표현, 모델 이름은 전달하지 않는다.

"다른 회사 모델이라서 더 엄격하다"는 성립하지 않는다. 근거는 **맹점이 덜 겹친다**는 것뿐이다. 익명화·독립 실행과 반드시 함께 건다.

반환 형식과 PASS 판정 기준, 편향 통제 규칙은 **references/cross-review.md**를 읽는다.

재검토는 **1회만** 한다. FAIL이 두 번 반복되면 Executor를 다시 돌리지 말고 메인이 개입하거나 Arbiter를 부른다.

## Phase 4 — 모델 배치

모델 이름은 **references/model-routing.md 한 곳에서만** 관리한다. 역할 프롬프트에 모델명을 중복해 적지 않는다.

요약하면:

```
기계적 추출·검색·짧은 요약        → gpt-5.6-luna low
제한된 조사·코드 탐색·문서 비교    → gpt-5.6-luna medium
근거 합성·계획 수립·가벼운 구현    → gpt-5.6-luna high 또는 gpt-5.6-terra medium
일반적인 코드 구현                → anthropic/claude-sonnet-5 medium 또는 gpt-5.6-terra medium
독립 리뷰                        → 작성 모델과 다른 회사, high
충돌 판정·고위험                  → gpt-5.6-sol xhigh 또는 anthropic/claude-opus-5 high
```

승격은 **실패 유형을 기록한 뒤에만** 한다. "답이 마음에 안 든다"는 승격 사유가 아니다. 동일 모델·동일 추론 강도 재시도는 최대 1회다.

## Phase 5 — 병렬 실행

동시 실행 슬롯은 보통 4개다. 메인 포함이므로 서브에이전트 3명 병렬이 안전선이다.

| 병렬 가능 | 병렬 금지 |
|---|---|
| 서로 독립적인 읽기 전용 조사 | 동일 파일 수정 |
| 서로 다른 모듈 탐색 | 선행 결과에 의존하는 작업 |
| 독립적인 테스트 결과 분석 | 하나의 API·스키마 동시 변경 |
| | Executor와 Reviewer 동시 실행 |

병렬 Explorer를 띄웠으면 `wait_agent`로 한 번에 수확한다. 서브에이전트의 주장은 **근거일 뿐**이므로, 결론 전에 서로 충돌하는 근거를 확인한다.

## Phase 6 — 종료

네 가지 상태 중 하나로 끝낸다.

```
DONE       구현·검증·리뷰가 모두 완료됨
BLOCKED    범위 밖 변경, 권한 부족, 요구사항 충돌로 진행 불가
ESCALATED  상위 모델 또는 Arbiter 판단이 필요함
PARTIAL    완료하지 못한 범위와 남은 작업을 명시함
```

**비용·반복 제한에 도달한 상태를 DONE으로 보고하지 않는다.**

최종 보고에는 실제로 사용한 모델과 추론 강도를 기록한다. 지정 모델이 거부돼 대체했다면 그 사실을 명시한다.

## 실행 로그

처음 20~30건은 자동 최적화를 시도하지 않고 기록만 쌓는다. 어떤 모델이 충분한지는 벤치마크가 아니라 이 로그가 판정한다.

**assets/run-log-template.md** 형식으로 남긴다. 사용자가 경로를 지정하지 않으면 로그는 생략하고 최종 보고에만 모델·결과를 적는다.

## 실패 시 대처

- **model override가 무시됨** — `fork_turns`가 `"none"` 또는 정수 문자열인지 확인한다. 전체 히스토리 포크는 override를 거부하고 부모 모델을 상속한다.
- **`Unknown model`** — references/model-routing.md의 대체 순서를 따르고, **회사를 유지**한다. GPT 자리를 Anthropic으로 메우면 교차 리뷰 구조가 무너진다.
- **서브에이전트가 계약을 어기고 범위를 벗어남** — 결과를 채택하지 말고 계약의 SCOPE·NON_GOALS를 좁혀 재호출한다. 같은 계약으로 재시도하면 같은 결과가 나온다.
- **Explorer가 근거 없이 단정함** — `path:line`이 없는 주장은 근거로 쓰지 않는다. 메인이 직접 해당 파일을 확인한다.
- **Reviewer가 취향 지적만 반환함** — BLOCKERS가 요구사항·계약 위반·보안·오류 처리·테스트 누락에 해당하는지 확인한다. 해당 없으면 NON_BLOCKING으로 내리고 PASS 처리한다.
- **서브에이전트 연결 실패·타임아웃** — 일시적 오류일 수 있다. 재시도하되, 조사 결과가 없는 상태를 "문제 없음"으로 해석하지 않는다.
